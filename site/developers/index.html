For developers

See a failure become a test.

Promtact runs a distributed system under deterministic virtual time and injected faults. If a property fails, the seed, step and trace turn that execution into a result another engineer can run again.

Explore the repository Read the developer guide 
git clone https://github.com/hunterinvariants/Promtact.git
cd Promtact

go test ./examples/paxos -v
go run ./cmd/promtact simulate \
  -config examples/leader-partition.json

Verification model

Four parts you can replace

Connect the system behavior that matters, state the safety boundary, choose the faults and preserve the resulting execution.

Protocol

Model the messages, nodes and transitions that define the system.

Properties

Evaluate invariants after each step and name the exact violation.

Faults

Exercise partitions, isolation, one-way links and bounded fault windows.

Storage

Bring the persistence behavior inside the same repeatable execution.

Concrete input

A scenario is reviewable data

Version the seed, node count, step budget and declared faults beside the code. The same input can run on a laptop, in CI and during review.

{
  "seed": "0x4A2C",
  "nodes": 5,
  "steps": 1200,
  "proposeEvery": 17,
  "faults": [{
    "type": "split",
    "a": [1],
    "b": [2, 3, 4, 5],
    "start": 200,
    "end": 700
  }]
}

Existing CI

Promote a reproduction into a gate

No required hosted runner or control plane. Keep deterministic tests and scenario files in the repository and run them in the CI system you already operate.

go test ./...
go test -race ./...
go run ./cmd/promtact simulate -config examples/leader-partition.json

Where it fits

Different tools answer different questions

Promtact

Deterministic simulation and replay with invariants checked after each step. A failed execution becomes a stable seed, step and trace.

Chaos engineering

Perturbs a live or staging system to observe resilience. Valuable for operational behavior, but not inherently deterministic or replayable.

External consistency checking

Tools such as Jepsen and Knossos analyze observed histories. They are complementary and also appear in Promtact's own qualification work.

Managed testing platforms

Provide a hosted testing environment. Promtact keeps local and CI execution available, while Enterprise adds a self-hosted operational boundary.

Start with evidence

Run the reference systems before adapting your own.

Inspect the source, scenarios and stated evidence bounds. If the model fits, connect the smallest correctness boundary that can reproduce your hard case.
